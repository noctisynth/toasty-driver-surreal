# RFC 工作流

RFC 用于记录会改变架构边界的工程提案。已经生效并持续约束实现的契约放在 `../specs/`；技术
验证证据放在 `../spikes/`；RFC 本身不代替实现清单。

## 状态

- `Draft`：正在探索或讨论，不构成实现授权。
- `Accepted`：核心决策、范围和验收标准已确认，可以同步 Active Spec 并建立实施清单。
- `Active`：RFC 本身被持续维护为现行架构决策；具体公共契约仍应落入相关 Spec。
- `Rejected`：提案未采用，保留背景与原因。
- `Superseded`：提案被后续 RFC 替代，必须链接替代文档。

## 编号与推进

RFC 文件使用四位递增编号和简短主题，例如 `0001-surrealdb-driver.md`。新提案先以 Draft 创建，
明确问题、目标、非目标、候选方案、影响、验收标准和待决问题。

本仓库为单一目标任务且无人工审阅门禁：RFC 由负责实现的 Agent 在自证边界清晰后自行转为
Accepted，随后按 `../DESIGN.md` 规定的顺序同步 Spec、TODO 与实现。转为 Accepted 前必须已经
存在可追溯的问题陈述、候选方案对比和验收标准。
